Workflow architecture: multi-agent disruption negotiation

How the ATC, pilot and ground AI agents resolve one real disruption from the 2015 US DOT flight data. Six stages run in at most three negotiation turns, with deterministic code making every safety call. Acacia Hackathon, AutonomousSG 2026, AI & Aerospace track.

Design principle: the AI agents argue, deterministic code decides. Agents declare limits and accept or reject proposals. The coordinator, solver, constraint checker and fallback are plain code, so the system always converges and can never commit an unsafe plan.

4. Message contracts

DisruptionEvent {
  event_id, scenario_type: WEATHER|KNOCK_ON|COMBINED,
  flight: {airline, flight_no, tail, origin, dest},
  sched_arrival, hist_arrival, hist_delay_min,
  causes: {weather, late_aircraft, air_system,
           airline, security},
  injected: [{type: RUNWAY_CLOSED, ref, duration_min}],
  turn: 1
}
ConstraintPacket {
  event_id, agent: ATC|PILOT|GROUND, turn,
  hard: [{id, rule, value}],       // never traded
  soft: [{id, preference, weight}],
  options: [{type: SLOT|GATE|ROUTE, value}],
  facts_owned: {...}               // owner wins on conflict
}
ResolutionPackage {
  event_id, package_id, turn,
  slot, gate, route_change,
  score, score_breakdown: {fuel, connections,
                           throughput, turnaround},
  satisfies_hard: true
}
Decision {
  event_id, package_id, agent, turn,
  verdict: ACCEPT|REJECT,
  reason_code: FUEL_LIMIT|GATE_CONFLICT|SEPARATION|
               CREW_DUTY|CONNECTION_RISK|null,
  rationale            // one line, for the log
}
ConsensusRecord {
  event_id, outcome: CONSENSUS|FALLBACK,
  package, turns_used, decisions[], checker_pass,
  delta_vs_history_min, signed_off_by
}

Conflicting facts: the owner's figure wins. Missing facts: the scenario builder injects a value, otherwise the conservative default applies.

7. How it meets the brief

Requirement or "avoid" itemWhere it's handled
Three independent domains, not one promptSeparate agent calls, each with its own prompt and private state. Agents only talk through the bus
No endless loopsThe coordinator's turn counter. Turn 3 forces commit or fallback
No disregard of safety marginsHard limits are filtered by the solver and re-checked by the checker. An LLM never commits
Structured messages + explicit constraint checkingPydantic-validated contracts and fixed reason codes
Traceable consensus logAppend-only log + ConsensusRecord
Deterministic non-AI fallbackFallback engine: first-come-first-served sequencing, earliest feasible gate, divert if the fuel limit is breached
Resolution in under 3 turnsThe happy path commits at turn 2

8. Assumptions and open items

  • Fuel, slots, gates, crew and connections are simulated with a fixed seed so every run is repeatable. They are labelled as simulated in the demo.
  • Rules of thumb (about 45 min US domestic fuel reserve, 35–60 min narrow-body turnaround) need checking before presentation.
  • Solver scoring weights are a design choice. They are shown in score_breakdown for transparency.
  • Suggested stack: Python, pandas, Pydantic, one LLM API with structured output at temperature 0, SQLite or JSONL log, Streamlit dashboard. No agent framework is needed.
